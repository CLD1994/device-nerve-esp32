# 编码器测量与主机有效性

## 契约

速度使用 17 个成功样本的位置差除以读帧完成时间差，不以任务名义周期换算。
默认采样仍为 1 kHz。窗口总跨度最多 32 ms；读取失败、非递增时间或相邻采样
超过连续性预算会清空窗口，重新积累样本前不发布有效速度。

| 状态 | 固件遥测 | 主机运动会话 |
| --- | --- | --- |
| 两路测量有效 | `VEL_VALID 1 1` 心跳及四字段 `STATE` | 仍需满足接收年龄、模式及原有门禁 |
| 预热、失败、过期、速度窗口超限 | 对应有效性为 0，不发送 `STATE` | 清缓存；活动会话锁存失败，不自动续跑 |
| 小车位置连续性丢失 | 小车有效性为 0，即使速度重新有效 | 禁止非零目标，需禁用后重新确认位置参考 |
| 有效性未知或主机心跳超时 | 固件不感知主机接收状态 | 禁止新的使能/非零速度，保留零速和禁用入口 |

连续性预算根据每转行程与参数注册表最高允许速度计算，以四分之一圈为工程裕量。
超过预算时不猜测空窗中的整圈数，而是保留累计基准并重新播种原始角度。
重新建立参考见[标定流程](calibration.md)，协议迁移见[协议说明](protocol.md#测量有效性)。

位置、速度与有效性从同一路快照读取；两路编码器不是同步采样。
`VEL_VALID` 不是磁场健康、无打滑或端到端时延证明。旧标量速度接口仅保留最后有效缓存，
不能独自用于停稳判断。运动消费者必须同时升级，不能忽略新增有效性行。

## 验证记录

2026-11-13 从实验分支拆出此能力，保留生产默认 1 kHz，不包含可选 2 kHz、
电流/速度/加速度默认值变更、STEP_LOSS 快照或实验运动脚本。

- 宿主测量快照、遥测组帧、编码器采样快照、参考点、真实时间速度窗、核心逻辑及 FSM 标定回归通过。
- Python 工具回归 88 项通过；原始系统 Python 缺少 pyserial，改用已有测试虚拟环境完成。
- 上游实验分支已有操作者提供的持续遥测和运动记录。这不等于拆分后固件重新完成硬件验收，
  也不证明所有故障注入、调度并发或物理停止场景。
- 此次环境没有 ESP-IDF 工具链，尚未对拆分后的提交进行目标构建或烧录。
