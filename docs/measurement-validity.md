# 如何判断编码器数据能否用于运动

小车位置和摆杆角度由两路磁编码器测量。一次串口读取成功，并不意味着速度已经可用：
速度需要一段连续的位置样本计算，位置还可能因为采样中断而失去累计圈数。
因此，运动程序必须同时检查数据和有效性，不能把缺失数据当成零速度。

## 从采样到测量

编码器每次读取成功后，发布一份快照，包含位置、原始角度、读取完成时间、样本序号和
速度估计。位置和速度来自同一路快照；两路编码器分别采样，不保证同一时刻完成。

默认 2 kHz 采样下，速度由最近 33 个成功样本的位移除以实际时间差得到，窗口通常约
16 ms；回退 1 kHz 时使用 17 个成功样本。窗口总跨度必须不超过 32 ms；时间不递增或采样间隔超过连续性预算时，
需要重新积累样本。小车读取失败即清窗；摆杆短暂失败保留成功窗口，具体限龄规则见下文。有效零速度与尚不可用的速度是两种不同状态。

小车位置解释组件负责把编码器计数换算成微米。应用初始化时向它传入最高允许线速度；
它结合每转行程计算时间预算，要求两次样本之间的预计位移不超过四分之一圈。
机械比例改变后，位置参考需要重新确认。组件不读取运动命令参数表，也不把当前低速命令
当作降低采样要求的依据。

## 接口中的有效性

编码器快照的各个字段回答不同问题：

- `valid`：是否曾取得成功样本，不表示样本仍然新鲜。
- `last_attempt_ok`：最近一次读取是否成功。
- `ok`：连续读取失败计数是否低于设备健康阈值。
- `velocity_valid`：速度窗口是否完整、时间连续、没有过期且编码器健康正常。

`cartpos_get_measurement` 和 `poleang_get_measurement` 返回整组测量是否可用。
小车还会检查机械比例、位置连续性和数值范围。成功时，位置或角度、速度、采样时间、
样本序号和速度窗口跨度一起返回；失败时不修改输出对象。调用方必须先检查返回值，
不得使用之前留在输出对象中的值作新测量。

这些接口判断“能否消费这组数据”，不是故障诊断接口。编码器快照保留采样、失败和连续性
序列，供需要区分原因的组件使用。单独的标量速度读取接口只返回最后有效缓存，不带有效性，
不能用于停稳判断。

## 上位机需要做什么

固件用 `STATE 独立有效位` 报告每路测量是否可用。这个名称不只表示速度窗口状态；
小车的累计位置失效也会令相应字段为 0。具体格式见[协议说明](protocol.md#测量有效性)。

| 接收情况 | 运动程序的处理 |
| --- | --- |
| 尚未收到所需路有效的 `STATE` | 不发送使能或非零速度请求。 |
| 两路可用 | 继续检查模式、状态接收年龄、同帧有效位与主机接收年龄、行程和命令续发期限。 |
| 所需路无效，或测量过期 | 清除缓存；正在运行的会话停止续发非零目标并尝试零速停机。 |
| 同一运行会话后来恢复为有效 | 保持中止，不自动继续运动。 |
| 小车位置连续性丢失 | 保持禁用，按[标定流程](calibration.md)重新确认位置参考。 |

串口缓存中的历史数据不会因为有效性改变而消失。主机接收时间不是设备采样时间，
`STATE 独立有效位` 也不是磁场健康、无打滑、端到端延迟或物理停车保证。

## 软件验证

运行方法与替身覆盖范围见[测量测试指南](../host_tests/encoder_reference_stubs/README.md)。
软件测试验证接口行为；目标平台构建、硬件时序与真实运动需要另外验证。

`vel` 调试仅以小车路作为运动观测，摆杆短暂无效仍报告但不单独停止；模型和其它双路运动工具仍要求两路有效。真实固件 FAULT 不豁免。线协议、规范无效占位及接收时效限制见[协议](protocol.md)。

## 摆杆短暂坏帧与速度窗口

摆杆实例保留最近成功样本组成的角速度窗口。短暂读取失败不会把坏帧插入窗口、刷新成功时间戳或推进位置展开；已有完整有效窗口、编码器健康正常且最后成功样本未过期时，继续上报最后成功的角度和角速度，STATE 摆杆有效位保持为 1；不是把失败帧当作新采样。设备端每次取快照按真实成功时间限龄，当前连续性间隔默认 20 ms，边界包含；超过该间隔即无效，重复发送不会续期。下一帧成功且与上次成功帧的间隔仍满足连续性要求时，使用保留的成功样本及真实时间跨度恢复角速度，不必重新等满一个窗口。

读取失败时若成功样本已超过连续性间隔、时钟相同或倒退，则清除速度窗口；成功读取时的长间隔/倒退处理和整个窗口最大 32 ms 限制保持不变。没有完整窗口、健康失效或样本过期时仍上报无效。连续十次失败的健康故障判据不变，不能用保窗绕过 MT6835 保护。

这个策略仅在组装摆杆实例时启用。小车实例保持读取失败即清窗的行为，其位置参考、连续性、故障判据和有效位没有放宽。
