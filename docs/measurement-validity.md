# 如何判断编码器数据能否用于运动

小车位置和摆杆角度由两路磁编码器测量。一次串口读取成功，并不意味着速度已经可用：
速度需要一段连续的位置样本计算，位置还可能因为采样中断而失去累计圈数。
因此，运动程序必须同时检查数据和有效性，不能把缺失数据当成零速度。

## 从采样到测量

编码器每次读取成功后，发布一份快照，包含位置、原始角度、读取完成时间、样本序号和
速度估计。位置和速度来自同一路快照；两路编码器分别采样，不保证同一时刻完成。

速度由最近 17 个成功样本的位移除以实际时间差得到。在 1 kHz 采样下，窗口通常约
16 ms。窗口总跨度必须不超过 32 ms；读取失败、时间不递增或采样间隔超过连续性预算时，
需要重新积累样本。有效零速度与尚不可用的速度是两种不同状态。

小车位置解释组件负责把编码器计数换算成微米。应用初始化时向它传入最高允许线速度；
它结合每转行程计算时间预算，要求两次样本之间的预计位移不超过四分之一圈。
机械比例改变后，位置参考需要重新确认。组件不读取运动命令参数表，也不把当前低速命令
当作降低采样要求的依据。

## 接口中的有效性

编码器快照的各个字段回答不同问题：

- `valid`：是否曾取得成功样本，不表示样本仍然新鲜。
- `last_attempt_ok`：最近一次读取是否成功。
- `ok`：连续读取失败计数是否低于设备健康阈值。
- `velocity_valid`：速度窗口是否完整、时间连续且没有过期。

`cartpos_get_measurement` 和 `poleang_get_measurement` 返回整组测量是否可用。
小车还会检查机械比例、位置连续性和数值范围。成功时，位置或角度、速度、采样时间、
样本序号和速度窗口跨度一起返回；失败时不修改输出对象。调用方必须先检查返回值，
不得使用之前留在输出对象中的值作新测量。

这些接口判断“能否消费这组数据”，不是故障诊断接口。编码器快照保留采样、失败和连续性
序列，供需要区分原因的组件使用。单独的标量速度读取接口只返回最后有效缓存，不带有效性，
不能用于停稳判断。

## 上位机需要做什么

固件用 `VEL_VALID` 报告两路整组测量是否可用。这个名称不只表示速度窗口状态；
小车的累计位置失效也会令相应字段为 0。具体格式见[协议说明](protocol.md#测量有效性)。

| 接收情况 | 运动程序的处理 |
| --- | --- |
| 尚未收到 `VEL_VALID 1 1` | 不发送使能或非零速度请求。 |
| 两路可用 | 继续检查模式、状态接收年龄、有效性心跳、行程和命令续发期限。 |
| 任一路变为 0，或心跳超时 | 清除缓存；正在运行的会话停止续发非零目标并尝试零速停机。 |
| 同一运行会话后来恢复为 `1 1` | 保持中止，不自动继续运动。 |
| 小车位置连续性丢失 | 保持禁用，按[标定流程](calibration.md)重新确认位置参考。 |

串口缓存中的历史数据不会因为有效性改变而消失。主机接收时间不是设备采样时间，
`VEL_VALID` 也不是磁场健康、无打滑、端到端延迟或物理停车保证。
