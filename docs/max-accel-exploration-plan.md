# 速度与加速度实测方案

本方案用于准备和记录倒立摆装置的执行能力测试。主机工具为
[`tools/max_accel_run.py`](../tools/max_accel_run.py)，硬件以
[hardware.md](hardware.md) 为准，命令以 [protocol.md](protocol.md) 为准。
`cartpole` 仓库的 `deploy/v2/sim2real-spec.md` 在取得可信实测结果后再调整。

## 参数与测量边界

`ACC_MAX` 是固件斜坡参数，默认 5000 mm/s²（5 m/s²），允许范围见协议注册表。
该参数、最高测试档以及没有触发 FAULT，都不等于机械最大加速度。
应记录实际供电、运行/保持电流、微步、传动比例、负载、温度及当前固件版本；
程序不会假定本次装置是 20 V、8 微步或旧行程。

当前小车位置来自板载 MT6835 对电机轴的测量，不能单独检测皮带与滑台之间的打滑。
往返净偏移只说明终点重复性；相反方向的误差可能相互抵消，速度跟踪误差、
中途丢步和传动弹性仍需结合轨迹及独立测量判断。
主机报告“完整通过”只表示规定的检查通过，不能作为机械无丢步认证。

## 运动前必须完成

1. 确认正式固件启动、控制 UART0 连接与 `DISABLED` 状态。原生 USB 是烧录/日志通道，
   不能仅凭 `/dev/ttyACM0` 存在便认定已连接控制通道。
2. 在禁用状态手推确认位置连续、方向正确；进行两点标定，并用尺量核对返回的 L。
   轨道更换或固件重启后不能沿用旧行程。标定命令见下文，不自动使能。
3. 保存 `CONFIG?` 参数及启动日志中的实际微步、换算比例与电气状态。
4. 确认独立断电/急停手段、运动空间与人员防护。固件软限位到达边界后才减速，
   不等于零制动距离；必须按当前行程、速度、制动和通信延迟留余量。
5. 人工确认完整试验轨迹可容纳后，单独决定是否发送 `ENABLE`。
   不将默认矩阵、回中速度或保持时间当成适合任意新装置的安全值。

## 子命令

所有命令在仓库根目录执行，需要 Python 和 pyserial。`PORT` 指实际控制串口。

```sh
python tools/max_accel_run.py --port PORT calib
```

`calib` 先查询 `DISABLED`，引导手推到两点并发送 MARK。
`MARK RIGHT` 回执直接是 L，不再减去左标记读数。完成后保持 DISABLED，
不发送 ENABLE、RESET 或运动命令。

完成上述运动前置条件及单独使能后，才可选择运动命令：

- `smoke`：5000 mm/s²、50 mm/s 一次往返。
- `matrix --speeds ... --accs ... --reps ...`：速度和加速度列表必须为严格递增的正整数，
  段数必须为正。默认候选值见脚本；首次使用应显式选择已批准的小范围，不能直接扫完整矩阵。
  每个速度组之前会以 100 mm/s 回中，进入中心带先制动并等待停稳。
- `step-response --step-v ...`：先请求零速并确认停稳，达到目标正向速度后保持 3 秒，
  然后请求零速并确认停稳。该位移可能大于往返试验的单程位移，必须单独检查空间。

往返单程保持时间由脚本 `LEG_PROFILE` 定义。到速时间上限为 `abs(v)/acc + 0.5 s`，
停稳时间上限为 `abs(v)/acc + 1 s`。这些时间是失效检测预算，不是运动范围保证。
低速指令接近速度噪声时，不能据此辨识准确加速度。

## 主机行为与失败语义

| 情况 | 主机行为 |
|---|---|
| 正负向速度到达 | 使用带符号目标及对称容差；零速或相反方向不算到达非零目标 |
| 模式不是 READY/NONE、没有状态或最新接收状态超过 100 ms | 结束当前运动入口，不再发送非零目标 |
| 加速到达超时 | 请求 `VEL 0` 并中止，不进入巡航 |
| 停稳超时 | 请求 `VEL 0` 并中止，不进入反向行程 |
| FAULT | 中止，不自动 RESET、ENABLE、回中或进入下一档 |
| Ctrl-C 或串口异常 | 请求 `VEL 0`，关闭会话；中断退出码为 130，普通失败为非零 |
| 配置回执缺失或与本次名称/数值不符 | 不开始该档运动 |
| 两程未完整完成、缺端点或遇到 FAULT | 该段 FAIL，不将未知偏移当作 0 |
| 完整两程净偏移绝对值 ≤100 µm / 100–300 µm / >300 µm | 分别标记 PASS / MARGIN / FAIL |
| 计划段数全部完成且全 PASS | 报告该档完整通过主机检查；否则不作为通过档位 |
| 首个非 PASS 或不完整段 | 保存已取得的结果并中止整个矩阵，等待人工检查 |

停稳需要连续 8 次**不同接收时戳**的检查结果满足 `abs(vx) ≤10 mm/s`，
每次轮询约 50 ms。重复读取同一帧不构成连续停稳证据。
参数或状态查询不替代独立停机条件。

发送 `VEL 0` 仅是尽力请求斜坡停止，并不是关闭使能。串口断开、主机阻塞或设备故障时
无法保证请求到达；固件看门狗也不是独立急停。必须由现场人员处理实际停机。

## 数据与结论

- `raw.log`：收到的串口行和主机相对接收时间。
- `segments.csv`：每个已返回试探段的结果、偏移、故障标记及原因。
- `summary.txt`：是否中止、完整通过的已测档位，不推断软件墙或机械极限。
- `step-response.csv`：保留阶跃期间收到的每一帧，字段为 `host_rx_t_s,x_um,vx_mm_s`。
  异常时也保存已接收部分。

当前协议没有固件采样时戳或帧序号。串口缓冲会使主机时间不同于设备采样时间；
因此保留全部帧解决了原来的 50 ms 抽样丢失，但不能直接保证能准确辨识 10–40 ms 的 τ。
需要先评估时戳/缓冲误差，再确定实测加速度、延迟与训练随机化范围。

## 软件验证与实机验证

软件回归使用标准库 unittest，不打开串口、不执行真实运动：

```sh
python -m unittest discover -s tools -p 'test_*.py' -v
```

这些检查覆盖方向、状态时效、超时、故障与退出副作用、标定回执和记录完整性。
真实设备的运动、制动距离、实际电流、编码器噪声、采样延迟及加速度包络须独立验收；
软件测试通过不代表已经完成这些实测。
