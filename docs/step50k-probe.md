# 单次50 kHz带载探针

[`tools/step50k_probe.py`](../tools/step50k_probe.py) 沿用现有有界主机会话，仅执行一次正向1250 mm/s、9000 mm/s²试验。它不是最大加速度自动搜索程序，不自动ENABLE、回中、反向、RESET或重试。

与完全离线的[预算器](step50k-plan.md)不同，此工具的 `plan` 会打开串口并查询模式、标定及配置，但不发送配置或运动命令。需要独立新日志文件，不覆盖历史结果。

```powershell
python tools/step50k_probe.py plan --port COM11 --baud 460800 --out step50k-plan.jsonl
```

保持时间及制动参数未确定时，计划保留未知，不能运行。`--help`列出参数。运行入口要求显式填写以下内容，没有默认运动方案：

- `--hold-s`：报告速度达到1250后的保持时间，可明确选0；滤波速度达标不证明真实瞬时速度。
- `--normal-decel`：在当前负载下可保证的正常制动减速度，不能高于将设置的ACC_MAX=9000。
- `--watchdog-decel`、`--watchdog-ms`：将设置的WDT_DEC及WDT_MS。固定25 ms续发、50 ms续发截止要求WDT_MS至少100；更短超时拒绝运行，避免正常续发期间先触发看门狗减速再重新加速。
- `--margin-mm`：正的额外距离余量。
- `--inflight-ms`：从最后非零写尝试开始计算的在途延迟上界预算，必须包含写调用本身的耗时、主机/USB/串口/固件排队；不能只填USB传输时间。
- `--window-s`：从首次非零写入开始的绝对非零时窗。
- `--normal-decel-evidence`、`--watchdog-decel-evidence`、`--inflight-evidence`：对应现场测量或预算依据的说明。
- `--confirm-motion`及`--confirm-clearance`：本次运行和现场条件的明确确认。

证据说明只是操作人声明，程序不能核验文字真实性。不得用占位文字或把未知延迟填写为0来绕过门禁。因此本页不提供填好数字的 `run` 命令。

## 预算与现场条件

固定采用已标定行程853.325 mm、软边界余量10 mm。读回不一致时拒绝，不擅自改变配置或按900 mm挡块间距计算。继承原预检的双侧位置余量检查，并进一步检查正向故障停车预算；不能从贴住左挡块的位置起步。

正常轨迹、整个非零时窗加在途延迟后的正常停车，以及带在途命令预算的看门狗停车，都必须放得进剩余行程。动态停止距离也在正常和看门狗两条路径分别加入在途距离，再取较大者；更强的看门狗制动不能代替较弱的普通制动预算。运行中逐帧检查反向、越界、超过预算速度及前方停止距离不足；不会因为同批后续帧恢复正常而取消中止。报告速度稍超1250也会中止，本探针不自动扩大速度阈值。

现场须核对当前固件和连续性保护版本、40 steps/mm比例、参考点、方向、磁铁和传动、20V供电、驱动电流及温度、真实净空、摆杆范围和可立即使用的独立断电措施。停止距离还依赖减速度可达、真实速度不超预算和命令延迟确有上界。

**当前协议没有独立固件绝对运动截止。** 主机绝对时窗和50 ms续发截止只约束主机行为；已经在途的VEL可能晚到并再次喂狗。证据文字和预算通过不产生硬件保证。软限位也不是提前制动，掉电或打滑可能使受控减速公式失效。

## 运行结果

run要求READY，不自动使能。正式配置前先尝试零速并观察静止；每项配置要求对应ACK，随后完整读回。再次确认静止和预算后才允许非零速度。运动阶段不写磁盘或输出进度；串口写入有20 ms超时，续发不能恢复错过的截止。

任何异常锁存本次失败。停止请求有界，并持续检查有效状态。探针记录最后非零写尝试的开始时刻，即使写入短缺或抛错也保留；从该时刻加声明的在途上界之前，任何静止状态都不能累积停稳窗口。在此期间仍持续请求零速、读取并保留异常。观察起点之后还须至少200 ms有效稳定状态；总停止截止另包含看门狗等待、按声明减速度计算的制动时间及0.5 s观测/处理预算。停止未确认明确记录，不能把串口写入成功当作停稳。该办法依赖声明的上界成立；没有设备时间戳，陈旧接收数据仍不能作为物理停止的硬证明。结束后不自动DISABLE，电机可能仍使能，用户须按现场停机流程处理。

最终停车路径首先不依赖时钟或日志尝试一次零速写入，再进入按时钟约束的零速与停止检查。时钟不可用时保留失败并报告停车未确认，不能声称截止有界或停稳。随后再尽力记录在途时间及结果。内存日志耗尽也不能跳过零速请求；记录失败使试验失败，二次日志错误不遮盖停车未确认警告。停止期间发送后的TX日志或读取时RX日志失败会保留为异常，持续有界零速尝试，不据此报告停稳。

JSONL包含计划、操作者三项证据声明原文及参数、原始字节、非零写尝试时刻、在途耗尽时间假设、发送命令、应用参数、停止及结果。声明记录标记为操作者提供且未经独立核验。`completed_received_state_checks_not_physical_acceleration_proof`只说明接收状态满足检查，不证明真实9000 mm/s²、50 kHz波形、无失步或无打滑。测量证据限制见[离线预算说明](step50k-plan.md#测量证据边界)。


### 到速识别与有界窗口结束

到速识别使用报告速度达到目标的 98%（1250 mm/s 的下界为 1225 mm/s），
仅是对滤波速度估计的近似判据，不证明实际精准达到 1250 mm/s、50 kHz 或 9000 mm/s²。
原有报告速度超过 1250 的中止保护、位置与失效保护均保持不变。
`hold` 从近似到速首次观察时计时；绝对非零窗口仍不可延长。
窗口正常耗尽会停止并记录 `motion_end.reason=window_elapsed`，
不会伪称达速完成；近似到速保持完成记录 `approx_target_hold_completed`。
两者都必须通过原停车检查才能正常返回。50 ms 续发截止仍为异常，
即使同时达到总窗口也优先中止；日志和输出明确区分这些原因。
