# 用 GPIO39 捕获摆杆读帧失败

这是诊断固件的可选示波器触发输出，默认关闭。启用后 GPIO39 为 3.3 V 推挽输出，启动初始化为低电平。只连接高阻示波器输入并共地，不要向此脚输入外部电压。

## 触发条件

1. 等摆杆编码器出现完整有效测量窗口，才获得布防资格。启动失败、窗口未填满时不触发。
2. 此后摆杆 `read_frame` 首次返回失败，GPIO39 置高并保持。SPI 事务错误、CRC 错误和全零帧拒绝都属于读帧失败。
3. 正常恢复、ENABLE、DISABLE、RESET、读取诊断都不清除锁存。只有设备重新启动才重新拉低并等待有效窗口布防。

GPIO 上升沿在失败读取函数返回之后，早于该次失败快照、失败计数和日志处理。该路径只执行一次置位，不添加延时、打印或 SPI 操作。它不是 SPI 波形中错误位的精确时间，也不是 FAULT 进入时刻；需观察沿之前的预触发波形。单纯速度窗口过期或其他测量有效性变化不会触发。小车编码器不驱动这个输出。

默认关闭时不配置 GPIO39，不在采样函数中编入触发回调或额外状态检查。开启后，任务每次成功采样检查一次有效性，失败时调用一次锁存逻辑；物理触发延迟和电平需在设备上验证。

## 构建与现场使用

在已同步的诊断分支中执行：

```sh
idf.py menuconfig
```

进入 `Component config → magnetic_encoder - 磁编码器类别`，启用 `GPIO39: latch first pole read failure after valid measurement`。保留其他现场配置，特别是摆杆 SPI DMA 开关、电流和串口设置，不为了本触发试验改变它们。

```sh
grep -n 'CONFIG_MAGNETIC_ENCODER_POLE_FAILURE_TRIGGER' sdkconfig
idf.py build
idf.py -p /dev/ttyACM1 flash
```

应显示 `CONFIG_MAGNETIC_ENCODER_POLE_FAILURE_TRIGGER=y`。烧录端口以当前设备实际端口为准。烧录会重启设备并重新布防；此处命令供操作者现场执行，脚本不会自动执行。

示波器把 GPIO39 接到独立通道，选上升沿触发（约 1.5 V），保留足够预触发数据，其他通道观察摆杆 SPI。GPIO39 在当前装置由操作者确认已引出且未占用；固件对 BSP 配置中主要外设及自定义控制台的 GPIO39 冲突做编译检查，但不能识别板外接线冲突。

完成后关闭同一选项并重新构建。关闭不会执行 GPIO 初始化；重启后引脚状态由芯片复位和板外电路决定，不承诺持续输出低电平。
