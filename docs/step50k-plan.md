# 50 kHz STEP 的离线带载行程预算

[`tools/step50k_plan.py`](../tools/step50k_plan.py) 对目标计算条件预算。目标速度固定为1250 mm/s，加速度由 `--acceleration` 选择100..30000 mm/s²整数（默认9000；软件配置范围，不代表已验证物理极限），40 steps/mm对应50 kHz。工具没有串口依赖，不读取设备，不配置参数，也没有 `run` 入口。

```powershell
python tools/step50k_plan.py plan
```

首次输出保留所有未定输入为 `null`。使用 `--help` 查看可显式填写的保持时间、正常减速度、看门狗减速度、超时、命令在途延迟、距离余量、非零窗口及起点。所有输入只作为计算假设，不是已经完成的硬件验证。退出码0只代表计算成功，`motion_authorized` 始终为 `false`。

## 坐标与停止预算

预算采用已测有效行程853.325 mm，而不是两端挡块间的900 mm。起点以左参考点为零，向右为正；前方软件边界为有效行程减去10 mm。软件边界之外的距离不计入可用预算。现场坐标、行程及余量与这些条件不一致时，不能使用该预算。

正常轨迹按加速段、指定保持段和正常减速段相加。正常减速度必须独立提供：当前普通 `VEL 0` 采用ACC_MAX，看门狗采用WDT_DEC，不能将二者混为同一停车路径。

故障预算采用整个非零窗口均按目标速度上限前进，再加命令在途延迟、看门狗等待、看门狗减速距离和额外余量。这避免依赖实际加速度必须达到目标值。公式仍有前提：实际速度不超过指定上限、给定减速度始终可达、在途延迟确有上界。

`conditional_normal_budget_fits` 和 `conditional_fault_budget_fits` 分别表示各自假设下是否放得进行程，不能互相替代。缺少必要输入时结果为 `null`。即使二者均为 `true`，也不是允许运动或硬件验收结论。

在途延迟必须覆盖主机、USB、串口和固件接收队列内最后非零命令的滞留。晚到命令可能再次喂狗，不能从主机最后一次调用 `write` 的时间直接推算固件看门狗停机上界。若无法给出延迟上界，需要实验专用固件绝对运动时限等独立约束，不能填写零隐藏未知风险。

现有软限位在越界后才钳制向外目标，不能承担提前制动。掉电、打滑或失去驱动力时，受控减速度公式也可能不成立。

## 运行探针的必要前置条件

本工具不提供可执行运动命令。未来运行探针需要独立审查：有效标定和方向、持续有效的采样、异常锁存、提前制动边界、命令续发与绝对截止、配置ACK及读回、有界停止请求，以及停止未确认时的现场措施。编码器间断必须清除停止判定缓存，后续恢复不能自动续跑。

保持时间和可保证的高速带载制动力尚未由工具选定。不能为了使预算通过而提高WDT_DEC；必须核对实际制动能力。

## 测量证据边界

500 Hz STATE接收记录只能支持接收频率、协议完整性、报告的有效性及接收到的停止状态检查。主机时间不是传感器采样时间，窗口滤波速度也不是逐点独立测量。

验证50 kHz实际输出需要外部STEP波形记录，检查周期、脉冲宽度、数量和缺脉冲。验证加速度需要采样时间戳、序号、编码器位置及速度窗口跨度等证据；接收统计不能独自证明所选实际加速度、无失步或无皮带打滑。输入预算中的减速度和延迟数字不构成这些证据。
