# 单次加速度基线复核

[工具](../../tools/accel_probe.py)只执行固定正向400 mm/s、5000 mm/s²、到速保持0.1 s的一次试验。不自动ENABLE、RESET、回中或反向。它验证的是收到的状态是否满足本次运行检查，不是机械最大加速度测量或硬实时安全认证。

## 前提和轨迹

人工核实供电20 V、已选择且核验的驱动电流、8细分、摆杆和机构状态、编码器比例，以及两侧实际净空。协议不能查询实时电压、电流或细分；READY只能提供固件供电门的间接信息。独立断电必须随手可达。

软件要求本次位置已参考、轨道保存有效、存储正常，并且起点到左右软件边界各至少250 mm。软件边界为±(标定长度/2−X_MARGIN_UM)。这些值不能代替尺量实际净空。

理想轨迹：加速80 ms/16 mm、巡航100 ms/40 mm、减速80 ms/16 mm，共72 mm。独立非零窗口0.23 s从首次非零写入之前开始，Windows调度延迟可能使试验中止，不自动延长。到速判据容差±5 mm/s。

正向相对100 mm触发停止并判失败；200 mm、反向3 mm或绝对软边界锁存严重越界。运动及停止循环不写控制台，完成有限停机处理后输出警告，避免输出阻塞延迟零速命令。停止阶段继续监视，危险帧不会被后续正常帧清除。阈值不是保证停止距离。按整个窗口满速再加WDT100 ms及DEC5000制动的理想估算为148 mm，仍未覆盖所有通信、机械和调度异常。

## 执行入口

先只读预检，新日志文件不能已存在：

```powershell
python tools/accel_probe.py --port COM11 --baud 460800 --out accel-plan.jsonl plan
```

下面命令会运动，只有完成现场单独确认、人工ENABLE且READY NONE后才可执行：

```powershell
python tools/accel_probe.py --port COM11 --baud 460800 --out accel-run.jsonl run --confirm-motion --confirm-clearance
```

run先以旧配置反复VEL0并检查至少200 ms速度≤1 mm/s、位置跨度≤100 µm，再逐项设置及完整读回：VEL_MAX400、ACC_MAX5000、WDT_MS100、WDT_DEC5000。再次确认静止后才发送非零目标。改变WDT_DEC100→5000增大制动冲击；沿用100会令400 mm/s的理想制动距离达到800 mm，不能沿用。试验结束不恢复旧配置。

首发前最多等待100 ms的新接收STATE；空的非阻塞读取不等于故障。非零目标以每次写入开始时间为基准约每25 ms发送，要求自上次发送后接收到新STATE；没有新帧时有界等待，不重发旧目标。运动期一旦距上次非零写入开始达到50 ms，立即中止，即使此时新帧刚到也不恢复非零；读前、读后、写前均优先检查50 ms续发截止和0.23 s运动截止。写入超时20 ms计入预算。这是主机本地约束，不保证设备看门狗绝不会先触发。异常后不再发送非零目标，最多1 s持续尝试零速和观察停稳。FAULT不自动清除；无法确认停止时立即使用独立断电。成功结束会打印结果，但不会自动DISABLE，READY下电机可能继续保持使能。

## 日志与证据边界

JSONL含原始接收字节、发送命令、预检、应用配置、停止和结果。日志先有界缓存在内存，结束才写盘，进程被强制终止可能没有完整日志。正常退出码0且存在result才表示本次主机检查完成；stop本身不能代替完整成功。

STATE没有设备采样时间戳或序号。接收时间和新接收行不能证明传感器实时新鲜；积压可能使位置监控滞后。500 Hz遥测在80 ms加速段名义约40帧，但串口批量传输、速度估计滤波和整数速度量化妨碍精确斜率估计。不得据此把指令5000当作实测5000，尾轴编码器也不能排除皮带滑动。
