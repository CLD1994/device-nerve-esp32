先阅读[入门与串口选择](../docs/getting-started.md)。串口工具的默认波特率不一定等于当前固件配置，始终核对 `--baud`。工具提供能力，不代表已经完成现场验证。

## 真机实验工具

这些工具不是生产控制器，也不自动恢复故障或使能。Python 串口入口依赖 `pyserial`，
在 Windows 原生终端运行；固件在 ESP-IDF 容器内构建。先阅读各入口的现场前提。

- [低速方向与停稳](../experiments/low-speed-probe/README.md)：小幅单向运动。
- [400 mm/s 加速度基线](../experiments/accel-5000-probe/README.md)：固定单次基线。
- [50 kHz 离线预算](../docs/experiments/step50k-budget.md)：不打开串口、不运动。
- [单次高速探针](../docs/experiments/step50k-probe.md)：显式预算输入，全部预算通过才允许执行。
- [两次往返探针](../docs/experiments/roundtrip-probe.md)：固定装置专用，低速接近端点，停稳后反向。
- [独立 STEP 测量固件](../experiments/step-frequency-isolated/README.md)：需物理隔离动力路径。

所有日志由用户指定新文件保存，不提交到仓库。实验结果不能替代实际速度、
加速度、温升、波形和停止距离的独立测量。对照记录见[实验结论](../docs/archive/2026-11-13-experiment-results.md)。

## 开发与维护边界

运动探针共用 [probe_link.py](probe_link.py) 的串口会话与预检，不依赖低速脚本的命令行入口。
串口、单调时钟与等待函数由构造参数注入；测试使用内存替身，不打开真实串口。
各运动脚本负责自己的轨迹、时限和停止条件。专用往返脚本不是训练控制器，
其风险确认不能替代通用控制器的制动设计。

这些文件不参与生产固件的构建，也不增加生产固件的常驻任务、内存或串口流量。
独立STEP工程需单独构建和烧录；它不运行生产模式机和编码器任务，
因而只能检查隔离条件下的STEP输出，不能替代完整固件的负载验证。

主机侧回归可在仓库根目录执行：

```bash
python -m unittest discover -s tools -p 'test_*.py'
bash experiments/step-frequency-isolated/tests/run.sh
```

前者验证主机工具的协议与行为，后者验证独立STEP测量控制逻辑。
ESP-IDF目标构建、波形和机械运动仍需在目标环境单独验证。

## 联调会话的 STEP_LOSS 事件策略

`cartpole_host.py` 严格识别 `EVENT STEP_LOSS <event_id> <run_id> <device_us>`，
不再将合法通知计为 UNKNOWN，也不把事件伪装成 MODE FAULT。事件 ID 和运行 ID
必须为非零 uint32，设备时间必须为非负 int64；畸形、未知事件和越界字段仍按原
UNKNOWN 规则处理，活动会话仍会中止。

全局选项 `--step-loss-policy report|stop` 必须放在子命令之前：

- `report` 是默认值：保存并显示合法事件，不清除最新 STATE、不改变测量有效性门禁，
  不因该事件自动发送任何指令；调用方原来的控制流程继续执行。
- `stop`：活动会话先保存事件并锁存中止，再通过异常交给命令入口；入口先尝试
  `VEL 0`，之后输出包含事件身份的原因，退出码为 1。零速请求不保证已经物理停稳。
  非活动会话仍只报告，不自动运动或使能。

例如只读观察事件可执行：

```powershell
python tools/cartpole_host.py --port COM11 --baud 460800 --step-loss-policy report state --secs 10
```

使用 `Rig` 的程序可通过同名构造参数 `step_loss_policy` 指定策略。`last_step_loss_event`
记录最近合法通知的 `event_id`、`run_id`、`device_us` 与 `host_received_at`；
`event_count` 是收到的合法事件行数，重复通知也计数，不代表独立故障数。
这些字段不证明事件属于当前运行，工具没有自动核验 RUN 身份，也不会把旧或重复通知
当作新运行。需要关联时调用方应自行核对运行身份。

`report` 不取消 STATE 独立有效位、未知数据、状态新鲜度或原有模式处理，也不会修改固件的
STEP_LOSS 停车/observe-only 配置。报告通过与 MODE/OK 相同的同步输出接口显示，
输出慢时可能阻塞；该联调工具不是硬实时控制器。`stop` 活动路径不先输出，避免在
零速请求前新增 stdout 阻塞。其他直接使用 Rig 的调用方须处理异常并请求停止，不能
假设 Rig 自行发出了零速。串口库仅在默认真实串口工厂使用时导入，内存替身测试不依赖设备。

### 按标定行程规划单向运行

`cartpole_host.py vel` 不指定 `--hold` 时默认按标定位置规划连续单程；只有显式 `--hold 秒数` 才使用按时长运行路径。
这是破坏性变更：`vel 600` 不再表示默认运行1秒；`--to-limit` 已删除且不接受旧语法。仅适用于支持统一 `ACC_MAX` 的新固件，旧固件不能套用本工具的停车预算。
`--plan` 选择只读单程规划，与 `--hold` 互斥。
首先使用只读规划，不发送运动命令：

```powershell
& $python $fwtool --port COM11 --baud 460800 vel 600 --plan
```

当前驱动短路原因尚未查清，此处不安排执行运动。`--plan` 仅发送 `CALIB?`、`CONFIG?`、`QUERY`，不会 ENABLE、RESET 或写配置。
正速度向右，负速度向左；`--reserve-mm` 默认20、`--inflight-ms` 默认10、`--max-seconds` 默认30。
规划读取完整标定状态（2/已保存/存储正常）、长度和实际运动配置，不猜默认值；执行还要求 READY NONE、新鲜有效状态与逐帧停稳证据。

目标位置为方向乘以 `长度//2 - X_MARGIN_UM - reserve_mm*1000`，会分别报告标定物理端、软件端和目标。
允许位于标定物理范围内、软件范围外的端点起步，但只能向内；进入软件范围后不能再次退出起点侧。
`--start-tolerance-mm` 默认0.5mm，可设0..1mm，仅用于起点读数微量超出标定物理端的向内运行；不扩大目标或制动预算。它是软件诊断容差，不是编码器精度校准或安全保证。仅对原起点位于物理范围外的向内恢复过程，允许相对最向内读数高水位不超过100µm的向外回撤；超过100µm即中止，连续小步外移同样累计，不能逐帧重置。所有恢复期位置还必须在物理端加起点容差的绝对范围内，100µm不会扩大该范围。为避免刚跨端点1µm又被噪声触发，向内达到物理端内100µm（含边界）才锁存恢复严格物理边界；此后再次出界拒绝。原本在物理范围内的起点始终按原严格边界，不启用恢复容差。100µm是固定软件噪声假设，并非传感器精度或现场噪声上界证明。起步前仍要求停稳，不能靠容差忽略非零速度。
固件是在越过软件边界时钳制向外速度，不是保证恰好停在边界。

正常提前制动预算取 `V × (max(观测年龄, 0.002) + inflight_ms/1000) + V²/(2×ACC_MAX)`（时间单位为秒），其中 `V=max(|请求速度|, |测得小车速度|)`。观测年龄仅为主机接收有效帧后经过时间。2 ms 是目标报告周期的相位下限，与年龄取最大值而非重复相加，并非最大帧间隔保证。
每帧及发送前按当前观测年龄重新检查；负年龄、超过100ms或非有限值仍拒绝，100ms失效门限没有放宽。
`--inflight-ms` 是可配置的调试延迟余量，默认10ms，未经过实测上界验证；可显式设50ms采用更大的余量，未自动假定零延迟。
固件负责组帧前样本新鲜度；正式帧不携带时间或身份。主机不能测出采样年龄、相对积压或完整通信延迟，刚从缓冲读出的帧仍可能已滞留。
单次查询到串口待接收量超过4096字节时拒绝继续非零，报告已观察的最大待接收量；不把分批读出的积压帧重新标时后当作充分新鲜。小于该阈值仍不能排除旧帧或证明端到端时效。

规划分别报告正常提前制动预算，以及额外加 `V×WDT_MS/1000` 的异常断链条件预算；后者只作风险说明，不作为正常零速触发提前量。
例如600mm/s、ACC_MAX=10000、观测年龄不超过2ms、默认inflight=10ms时，正常预算25.2mm（7.2+18）；WDT_MS=100时异常断链条件预算85.2mm。断链或主机停顿可能越过目标，固件WDT及主机过期、超速、故障和边界门禁仍保留。
两次±600现场样本在请求零速后移动20.492mm及20.655mm，只说明这两次结果，不构成最大停车距离或10ms延迟上界证明。
预留量已扣进目标，不重复加入预算。剩余距离不足就拒绝起步，不自动降速或反向。上述公式与余量都不是物理安全保证。
当前模式保持连续单程：有效非零行程止于提前制动点，预算较大时不能跑满轨道；不保证恒速区间长度或精确抵达目标。分段低速接近仅是后续可选方案，当前未实现。

执行按收到的位置决定何时发零速，而不是按时间定位；每个STATE检查目标侧边界、物理边界、反向超过3mm及超速。
未知/失效/过旧状态、模式离开READY、最长期限或续发超时都会停止非零命令。非零发送不快于20ms一次，不补发追赶；
WDT_MS不大于20会拒绝，主机续发间隔及写入耗时不得达到min(50ms,WDT_MS)。这不是实时调度保证。
合法STEP_LOSS仍遵循全局report/stop策略，report不等于忽略FAULT。

新模式结束先发零速，并在有限2秒确认窗口重复请求零速；在途假设窗口过去后，仅新STATE连续200ms报告vx=0且位置范围不超过100µm才报告收到停稳证据。
这不能证明真实机械位置或物理安全。未确认会明确返回失败；报告零速请求位置、最终收到位置和距目标差，不宣称精确定位。
活动阶段协议文案暂存最近128条，先完成零速与有限停车观察再输出，避免输出阻塞停车请求。
旧hold正常结束仍沿用原pump/WDT行为，未被改成主动零速。

### vel 的主机计时观测

每次 `vel` 从命令处理入口启用单调时钟记录，退出并完成原有清理/关闭串口后输出一次摘要，不新增运动、配置查询或等待。总耗时不包含打开串口和入口前对齐时间。
默认摘要为中文分行，不输出JSON：阶段时点以命令入口为零点，用秒（s）；时间间隔用毫秒（ms），总耗时用秒。未发生的写入、未观测的速度及未确认的停稳分别标明，不填成0。以下字段名称仅说明内部统计含义，不是默认终端输出格式。内部 `command_start_monotonic_s` 是该主机时钟读数，不是设备时间或跨主机时间。

- `query_complete_s`：单程只读查询完成；`preflight_complete_s`：单程READY及原有起步停稳检查完成，或hold原有READY检查完成。
- `first/last_nonzero_attempt_s` 和 `first/last_nonzero_complete_s`：首末非零主机write尝试与完整返回；短写/抛错只留下尝试，完成字段不伪造。
- `first_nonzero_vx_received_s`：首次非零write尝试以后收到的首个非零编码器速度。此前预检速度不计入本次响应、峰值及样本数。
- `first_zero_attempt_s`、`first_zero_complete_s`：首次零速写入尝试/完整返回，后续重复零速不覆盖。
- `stop_observed_s`：仅引用单程原有停稳确认；`zero_to_stop_observed_s` 为对应接收确认间隔。
- `command_elapsed_s` 为包含预检和原有收尾的总耗时；`nonzero_attempt_span_s` 是首末非零write尝试间隔，不是机械运动时长。

内部缺省值保持 `None`，摘要显示“未发生／未观测／未确认”。显式hold的原time.time调度、收尾0.3秒pump及WDT行为不变，正常结束没有主动零速，因此摘要显示零速请求“未发生”、停稳“未确认”；末帧vx=0不替代可靠停稳证据。速度为0的hold也不计作非零发送。

`received_response_interval_s` 只是首次write尝试到首次非零速度接收的间隔；写入完成只说明主机驱动接受，不代表线路发送完成或固件收讫。速度峰值、样本数与接收时间受缓存延迟、滤波和噪声影响，短写后观测也不能证明设备执行了完整命令。这些统计不证明准确加速度、真实机械起停或ACC_MAX已经达到实测值；不能仅凭vel总耗时确认5000mm/s²生效。

停车清理将运动失败锁存与观测资格分开：任何原失败仍禁止后续非零VEL和ENABLE，命令结果仍失败；仅在首次零速请求后重建独立的停稳观测资格。入口清除旧观测，必须收到后续所需通道有效的 STATE 才累计停稳；协议不能识别设备重复样本。未知、损坏或失效数据清除观测资格并重置连续停稳窗口；后续重新合法的数据可再次累计，但不能解除运动失败。异常后收到停稳证据会填写stop_observed_s，这仍只是接收状态确认，不是机械停止真值。Ctrl+C明确显示“用户中断”，不以空字符串掩盖原因。

摘要中的目标95%达速估计使用本次首次非零命令的目标速度，不使用VEL_MAX：例如目标1000mm/s，门槛为同向950mm/s，而不是要求精准到1000或达到1250。时间从主机首次非零写入尝试到首次收到同向至少95%目标的速度；必须已有完整非零write返回，且尚未请求过零速。预检样本、反向速度、零速后的速度均不算达成；未完整写入显示“未确认完整非零写入”，已写入但未过门槛显示“未观测到达成”。

该间隔只是接收达速估计，不证明从静止起步：hold开始时可能已在移动，接收帧也可能缓存、延迟或经过滤波。它不是准确物理加速时间或ACC_MAX生效证明，不额外读取ACC，也不推算理论v/a。运动与停车逻辑不因该统计改变。

未达到95%门槛时，摘要补充“加速阶段同向峰值”和首次达到该峰值的主机接收耗时。该阶段仅包括完整非零write返回后、首次零速请求前；同一峰值重复出现不覆盖首次时刻，反向速度和停车后的速度不更新该峰值。耗时仍从首次非零写入尝试起算，不能解释为从静止开始的真实机械加速。

“结束最新速度”独立列出最后接收的vx，仅当所需通道有效、主机接收后年龄不超过100ms时显示，否则为“未确认”。该资格检查不改变运动失败锁存；显示停车后的0不覆盖加速阶段峰值，也不表示实时仪表读数。会话全段绝对速度峰值仍单独保留，不能与同向加速峰值混用。

### 失败首因与原始接收证据

工具保留会话首次主机检测条件，收尾在原有零速处理、串口关闭后才打印诊断，不增加运动命令或改变门禁。诊断给出原因分类、主机读取处理/发现时的monotonic时间、相关原始串口行，以及最多4条前文。每行仅保留前256字节并标记原始长度和截断；输出用字节转义表示控制字符及非ASCII字节，不能把截断内容当完整报文。

无效 flags、畸形STATE/MODE/EVENT及未知行可关联本行原始字节；测量过期、写入异常、缓冲/积压限制、本地时序及仅发现既有failed锁存时可能没有触发行，明确显示“无原始行”。迟到的正常状态帧不能覆盖此前超时，也不能被误标为损坏触发帧。后续正常行或停车过程不覆盖首次记录。

这记录的是主机首先发现的条件，不等于硬件根因。时间不是设备发送/采样时刻；工具没有CRC校验能力，不会据此声称CRC错误。直接调用解析函数而非串口接收路径时也可能没有原始字节证据。上下文有界，只用于定位，不是完整串口日志。

### 摆杆失效首证据

`pole_diag_capture.py --port COM11 --baud 460800 --out <新文件.json>` 只读导出已编入的摆杆测量失效快照，不改变设备状态。须先停机，完整响应才保存，失败不自动重试运行。构建选项、字段和证据边界见[摆杆失效诊断](../docs/pole-diagnostic.md)。

### `vel` 小车独立调试路径

`vel`（默认单程、显式 `--hold` 定时）仅依赖统一 STATE 内有效、新鲜的小车路。摆杆无效会有界计数并在结束后汇总，不构造虚假的摆角；真实 FAULT、小车无效、损坏/未知帧、接收过期仍停止。`--plan` 仍只读。其它双路运动工具及模型要求两路有效。固件与工具必须一起升级，不再需要独立小车流开关，旧帧不兼容。

正常制动预算：`V × (max(观测年龄, 2 ms) + --inflight-ms) + V²/(2×ACC_MAX)`，其中 `V=max(|请求速度|, |测得小车速度|)`。2 ms 为目标报告周期的相位下限，不保证最大间隔；与已经累计的年龄取最大值而不重复相加。默认在途 10 ms 仍是未经实测的调试假设。1000 mm/s、ACC_MAX=10000、足够新鲜的样本对应 62 mm（2+10+50）；异常断链条件预算另加 WDT_MS 距离。这不是有保证的物理停车上界。

年龄仅为主机接收后经过时间，不能证明串口排队延迟；没有样本身份，不能识别重复采样。所需路接收年龄超过100ms拒绝。目标 500 Hz 并非实际精确 2 ms，达到 95% 目标速度仍只是编码器接收观测时间。

正常 `--hold` 结束仍遵循停止发送与固件 WDT 行为，未新增正常退出 VEL 0；单程或异常清理请求零速。观测到停稳不解除原失败锁存。

回归：`python -m unittest discover -s tools -p 'test_*.py'`、`bash host_tests/test_telemetry_timing.sh`。正式帧不带身份或时钟，不能保证识别重启、旧帧或重复采样；模式异常和接收超时仍拒绝。线格式与有效性见[协议](../docs/protocol.md)。
